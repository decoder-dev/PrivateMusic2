# Схемы сборки и установки Private Music 2.0

## Рекомендуемая сейчас

### GitHub Actions → unsigned IPA → ESign

1. Исходники помещаются в GitHub-репозиторий.
2. Workflow `Build unsigned IPA` запускается на macOS.
3. Xcode компилирует arm64-приложение без подписи.
4. Workflow создаёт `PrivateMusic-2.0-unsigned.ipa`.
5. IPA импортируется в ESign и подписывается имеющимся сертификатом.

Плюсы: не нужен собственный Mac; ESign получает чистый IPA, а не исходники.

Минусы: качество установки и срок действия зависят от сертификата ESign.
Следует отключить любые dylib/deb/tweak-инъекции.

## Бесплатная официальная подпись

### GitHub Actions → unsigned IPA → AltStore Classic

AltStore подписывает IPA через обычную учётную запись Apple. Для бесплатной
Personal Team приложение действует 7 дней и требует регулярного обновления.
Apple также ограничивает число одновременно активных sideload-приложений.

Плюсы: не нужен купленный сертификат.

Минусы: 7-дневный срок, ограничения бесплатной учётной записи и необходимость
AltServer/AltStore.

## Стабильная личная подпись

### Apple Developer Program → Ad Hoc/Development IPA

Потребуются:

- членство Apple Developer Program;
- сертификат `.p12`;
- provisioning profile;
- UDID устройства для Ad Hoc/Development установки.

Эти файлы можно хранить в зашифрованных GitHub Secrets и подписывать IPA в CI.
Секреты нельзя коммитить в репозиторий или отправлять в открытом виде.

Плюсы: предсказуемая подпись и отсутствие зависимости от публичных сертификатов.

Минусы: платное членство и первоначальная настройка.

## Альтернатива GitHub

Codemagic и Bitrise также предоставляют macOS/Xcode runners. Архитектура та же:
Xcode build → `.app` → `Payload` → IPA → подпись. Для текущего проекта GitHub
Actions уже настроен, поэтому переход на другой сервис не даёт технического
преимущества.

## Что не рекомендуется

- публичные или «слитые» enterprise-сертификаты;
- отправка Apple ID, `.p12` или пароля неизвестному онлайн-подписанту;
- автоматическая инъекция dylib/deb;
- подмена bundle ID после компиляции без повторной подписи;
- публикация access token VK в CI secrets, логах или исходниках.
